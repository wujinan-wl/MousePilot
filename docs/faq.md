# MousePilot 常見問題（FAQ）

## MousePilot 沒有觸發自動移動，為什麼？

依序檢查：

1. **狀態是否為「已暫停」**：Dashboard 狀態點若是灰色「已暫停」，代表監控根本沒開始。按「啟動 MousePilot」（或系統匣選單「啟動」、快捷鍵 `Ctrl+Alt+F9`）。
2. **閒置時間是否真的到了**：狀態點為「等待啟動」（黃色）時，「距離第一次觸發」欄位會顯示倒數秒數；只要期間有任何鍵盤/滑鼠操作，倒數會重置，這是設計上的行為（不是 bug）。
3. **是否進入「錯誤」狀態**：紅色狀態點「錯誤（滑鼠移動失敗）」代表移動連續失敗 3 次已停止再嘗試觸發。查看 `%AppData%\MousePilot\Logs\mousepilot.log` 是否有對應的 `ERROR` 記錄；按一次「啟動」或「暫停」即可解除紅點重新開始監控。

## 套用自訂游標後想恢復成 Windows 原本的游標，怎麼做？

四種方式都可以（詳見 `docs/user-guide.md` 9.4 節）：

1. Dashboard「游標設定」卡片的「恢復 Windows 游標」按鈕。
2. 系統匣右鍵選單的「停用自訂游標」或「恢復 Windows 游標」。
3. 全域快捷鍵（預設 `Ctrl+Alt+F10`）。
4. 若程式本身開不起來或卡住，可在命令列直接執行 `MousePilot.exe --restore-cursor`——這個參數會立刻恢復 Windows 游標並結束，**不受單一實例限制**（就算已經有一個 MousePilot 正在執行，這個指令仍會獨立執行恢復動作），適合緊急救援使用。

## MousePilot 異常關閉（crash）後，游標卡在自訂樣式沒有變回來，怎麼辦？

正常情況下不需要手動處理：MousePilot 在套用自訂游標時會先寫入一個內部標記檔 `cursor-applied.marker`（`%AppData%\MousePilot\`），只有在成功恢復後才會刪除。若程式異常結束（crash、強制關閉）沒有機會執行恢復流程，這個標記檔會留下；**下次啟動 MousePilot 時會自動偵測到這個標記並先執行一次恢復**，之後才繼續正常啟動流程。

如果暫時不方便重新啟動 MousePilot，也可以直接執行 `MousePilot.exe --restore-cursor` 立即恢復游標。

## 開啟第二個 MousePilot.exe 沒有反應，是不是壞了？

沒有壞掉，這是**單一實例**設計：MousePilot 一次只允許一份在同一個 Windows 使用者登入階段中執行。第二次啟動時，程式會偵測到已有實例在跑，直接通知原本那個實例把 Dashboard 視窗喚醒顯示出來（即使原本縮在系統匣也會跳出來），然後第二個程序自己結束，不會多開。如果沒看到視窗跳出，檢查看看視窗是不是被其他視窗擋住，或工作列上是否已經有一個 MousePilot 圖示。

## 我的電腦有多個 Windows 使用者帳號，可以每個人都各自跑一份 MousePilot 嗎？

可以。單一實例的判斷是綁定在**目前登入的 Windows 使用者工作階段**，不同使用者各自登入後執行 MousePilot，會各自視為獨立的第一實例，互不影響、可以同時各自執行一份，各自的設定/Log 也各自存放在該使用者自己的 `%AppData%\MousePilot\`。

## 全域快捷鍵沒有作用？

常見原因：

1. **被其他程式占用**：Windows 全域快捷鍵是系統唯一的，若其他程式（例如另一套工具或系統本身）已經註冊了同樣的組合鍵，MousePilot 會提示「快捷鍵 ⟪組合⟫ 已被其他程式占用」並自動還原成原本設定，需要改用其他組合鍵。
2. **`settings.json` 被手動改壞格式**：快捷鍵字串格式嚴格區分大小寫，正確格式例如 `Ctrl+Alt+F9`（修飾鍵字首大寫，`+` 連接）。如果手動編輯設定檔把大小寫寫錯（例如 `ctrl+alt+f9`），程式會判定該字串無效，直接**停用**對應的快捷鍵（不會自動修正大小寫），啟動時 Dashboard 會出現「快捷鍵設定「⟪內容⟫」無效，⟪功能⟫ 快捷鍵未啟用。」的提示，Log 也會記一筆錯誤。回到 Dashboard 用滑鼠點欄位重新錄製一次即可修復。
3. **兩組快捷鍵設成同一組合**：啟動/暫停與恢復游標的快捷鍵不可重複，設定時會提示「快捷鍵不可與另一項重複。」。

## 匯入圖片後游標看起來變形或整張變空白，為什麼？

- **變形**：不會發生比例被拉伸的情況——匯入的圖片一律先自動裁切透明邊界，再等比縮放置中放入所選的正方形尺寸畫布，不會強制拉伸變形；如果視覺上覺得「變形」，通常是原圖本身長寬比例差異較大，等比縮小後在正方形畫布中會留白邊，這是保持原比例的正常結果。
- **整張變空白**：常發生於勾選「移除背景（JPG 建議）」但容差設太高，把整張圖的內容都當成背景去除掉了。此時程式會顯示警告「去背後沒有可見內容——請降低容差或關閉去背。」，並且不會產生可套用的游標；請降低容差數值，或取消勾選去背後重試。

## 防毒軟體對 MousePilot 提出警告，正常嗎？

MousePilot 為了達成「自動微移滑鼠防止待機」的核心功能，會呼叫 Windows API 送出模擬滑鼠輸入（`SendInput`），這類行為與部分「巨集/自動化」類軟體的行為模式類似，可能被部分防毒/安全軟體標記為需要留意的行為，這是誤判機率較高的正常現象，並非惡意行為。MousePilot 是純本機執行的工具，不連網、不上傳任何資料、不需要系統管理員權限；原始碼公開可自行稽核（見專案 GitHub repository）。若擔心，可先閱讀原始碼中 `Native/NativeMethods.cs`（所有 Win32 呼叫集中處）與 `Services/MouseMovementService.cs` 確認實際行為後再決定是否信任執行。

## MousePilot 會不會一直佔用 CPU？

不會。閒置偵測固定使用 500 毫秒一次的計時器輪詢 `GetLastInputInfo`，並非高頻 Hook 或忙碌迴圈（busy loop），常態 CPU 使用率接近 0%。滑鼠微移本身也只在真正閒置達到設定秒數時才短暫觸發，不會持續耗用資源。

## 為什麼 MousePilot 沒有自動更新、沒有雲端同步、也不需要帳號登入？

這是刻意的設計取捨。MousePilot 第一版的定位是「純本機 Windows Local Utility」，明確排除帳號系統、Cloud Sync、資料庫、Web/API Server、自動更新系統、遠端控制等會引入額外相依、隱私與安全風險的功能，只專注做好本機防閒置與游標自訂這兩件事。新版本會透過 GitHub Releases 手動下載，不會有背景自動更新行為。
