# MousePilot 發布驗證清單

本清單供 v1.0.0（或後續版本）正式發布前的**實機手動驗證**使用，涵蓋規格 `docs/spec/mousepilot-spec.md` §三十四全 31 個測試案例，以及歷代 Phase 開發過程中累積、但 §34 未直接涵蓋的補充驗證項目（已去重整合，不重複列出 §34 涵蓋的行為）。

每項操作步驟與預期結果皆依實際實作行為撰寫，細節可另外參考 [使用說明](../user-guide.md)、[FAQ](../faq.md)、[Debug 方法](../debugging.md)。

## 0. 前置

1. 依 §39 驗收指令，於乾淨環境（開發機）跑完整流程：

   ```powershell
   dotnet restore
   dotnet build -c Release
   dotnet publish -c Release -r win-x64 --self-contained true /p:PublishSingleFile=true
   ```

   確認 0 error、0 warning，且於 `bin\Release\net8.0-windows\win-x64\publish\` 產出 `MousePilot.exe`。

2. **乾淨環境驗證**：把上一步產出的 `MousePilot.exe` 複製到另一台**沒有安裝 .NET 8 Runtime** 的 Windows 10 或 Windows 11 x64 電腦（或乾淨的虛擬機），直接雙擊執行，確認可以正常啟動（self-contained + single-file 應無需額外安裝任何 Runtime）。

## 1. §34 測試案例（全 31 項）

### Idle（1~5）

- [ ] **案例 1：使用者持續操作鍵盤，不觸發。**
  操作：把「開始閒置」暫調為 10 秒方便測試，持續打字不間斷（不要停下）。
  預期：狀態點維持綠色「監控中」／「使用者活動中」，不會進入「等待啟動」，不觸發自動移動。

- [ ] **案例 2：使用者持續移動滑鼠，不觸發。**
  操作：同上設定，持續移動滑鼠（不打字）。
  預期：同案例 1，狀態維持綠色，不觸發。

- [ ] **案例 3：滑鼠鍵盤都停止後才觸發。**
  操作：鍵盤滑鼠都放開，等待滿「開始閒置」秒數（如 10 秒）。
  預期：狀態變黃色「等待啟動」／「自動移動中」，倒數歸零後觸發一次自動移動，「觸發次數」+1。

- [ ] **案例 4：Idle 期間重新操作後取消。**
  操作：把「開始閒置」設 5 秒，倒數剩約 2 秒時動一下滑鼠（或按一下鍵盤）。
  預期：狀態立即變回綠色「使用者活動中」，「距離第一次觸發」倒數重置，不觸發移動。

- [ ] **案例 5：自動移動後等待下一次間隔。**
  操作：接續案例 3 讓第一次移動觸發後，持續放開不動。
  預期：「距離下一次移動」依「後續移動間隔」秒數倒數，時間到再次觸發移動，「觸發次數」再 +1，如此週期性循環。

### Mouse Movement（6~12）

- [ ] **案例 6：左右模式正常。**
  操作：移動模式選「左右移動」，按「立即執行一次」。
  預期：滑鼠沿 X 軸移動「移動像素」設定的距離，Y 座標不變。

- [ ] **案例 7：上下模式正常。**
  操作：移動模式選「上下移動」，按「立即執行一次」。
  預期：滑鼠沿 Y 軸移動指定像素，X 座標不變。

- [ ] **案例 8：Random 正常。**
  操作：移動模式選「隨機方向」，連續按「立即執行一次」數次。
  預期：每次移動方向隨機（不固定單一軸向），移動距離符合「移動像素」設定，且目的座標合法（不出界）。

- [ ] **案例 9：Return Position 正常。**
  操作：勾選「移動後回到原位置」，按「立即執行一次」。
  預期：微移後約 300 毫秒滑鼠自動移回原本座標。

- [ ] **案例 10：螢幕邊界正常。**
  操作：把滑鼠移到螢幕最右緣（或最上/最下緣）附近，再按「立即執行一次」。
  預期：移動方向在碰到邊界時自動反向，游標不會被移出螢幕邊界。

- [ ] **案例 11：多螢幕正常。**
  操作：（需多螢幕環境）把滑鼠移到副螢幕上，按「立即執行一次」。
  預期：移動正常發生在副螢幕的 Virtual Screen Bounds 範圍內，不假設座標一定落在主螢幕。

- [ ] **案例 12：負座標正常。**
  操作：（需副螢幕位於主螢幕左側或上側的多螢幕環境）把滑鼠移到負座標區域，按「立即執行一次」。
  預期：移動計算正確、不出界、不例外，座標處理不假設 X/Y ≥ 0。

### Cursor（13~22）

- [ ] **案例 13：PNG 匯入。**
  操作：按「匯入圖片」，選一張含透明背景的 `.png`。
  預期：匯入成功，顯示檔名與尺寸，檔案出現在 `%AppData%\MousePilot\Cursors\`。

- [ ] **案例 14：JPG 匯入。**
  操作：同上選 `.jpg`/`.jpeg`。
  預期：匯入成功。

- [ ] **案例 15：BMP 匯入。**
  操作：同上選 `.bmp`。
  預期：匯入成功。

- [ ] **案例 16：CUR 匯入。**
  操作：同上選 `.cur`。
  預期：匯入成功，尺寸與 Hotspot 直接取自檔案內容（編輯器尺寸下拉停用）。

- [ ] **案例 17：ANI 匯入。**
  操作：同上選 `.ani`。
  預期：匯入成功（預覽取首格，若首格本身視覺較空亦屬正常）。

- [ ] **案例 18：Hotspot 正常。**
  操作：開啟編輯器，點擊中欄預覽圖任一位置；再手動於 Hotspot X/Y 欄位輸入數字。
  預期：點擊後十字標記移到該位置、欄位即時更新；手動輸入值同樣生效，且自動夾制在 `0` 到「目前尺寸 - 1」之間。

- [ ] **案例 19：Preview 正常。**
  操作：把滑鼠移入編輯器右欄白底、深底兩個示範區塊（含按鈕/Checkbox/連結/文字框）。
  預期：游標即時變成所選自訂游標樣式，Hotspot 位置正確（點按鈕手感對）；移出示範區塊後，Windows 全域游標完全不受影響。

- [ ] **案例 20：Global Cursor 正常。**
  操作：編輯器選一個圖案（如「愛心」）→按「套用」（或先「確定」再於 Dashboard 按「套用」）。
  預期：Windows 全域游標（桌面、其他程式）變成所選圖案；Dashboard「游標」狀態顯示「已套用自訂游標」，並跳出「已套用自訂游標。」提示。

- [ ] **案例 21：Restore Cursor 正常。**
  操作：套用狀態下，依序用 Dashboard「恢復 Windows 游標」按鈕、Tray「恢復 Windows 游標」、快捷鍵 `Ctrl+Alt+F10` 三種途徑各測一次。
  預期：三種途徑皆能立即把游標恢復成使用者原本的 Windows Cursor Scheme。

- [ ] **案例 22：關閉程式後 Cursor 正常恢復。**
  操作：套用自訂游標狀態下，用系統匣選單「結束」正常關閉程式。
  預期：關閉瞬間游標恢復為 Windows 原本樣式，不殘留自訂游標。

### Windows Integration（23~28）

- [ ] **案例 23：Registry Startup 正常。**
  操作：勾選「Windows 開機時自動啟動」，PowerShell 執行 `Get-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Run' -Name MousePilot`。
  預期：顯示引號包覆的 EXE 完整路徑。

- [ ] **案例 24：關閉 Startup 後 Registry 清除。**
  操作：取消勾選後，執行同一條指令。
  預期：報「找不到屬性 MousePilot」（值已被移除）。

- [ ] **案例 25：Tray 正常。**
  操作：啟動 `MousePilot.exe`；雙擊系統匣圖示；右鍵系統匣圖示。
  預期：預設不顯示視窗、系統匣出現圖示；雙擊開啟 Dashboard；右鍵顯示完整選單（開啟／啟動／暫停／立即執行一次／游標三項／設定／結束，含分隔線），尚未選游標時游標三項為灰色不可用。

- [ ] **案例 26：Global Hotkey 正常。**
  操作：Dashboard 縮在系統匣（視窗不在前景）時按 `Ctrl+Alt+F9`。
  預期：監控啟動/暫停狀態切換，Tray tooltip 與選單啟用狀態同步更新，不需要 MousePilot 視窗在前景。

- [ ] **案例 27：Hotkey 衝突正常處理。**
  操作：讓另一程式先佔用某組合鍵，或改用已知系統保留組合，嘗試把 MousePilot 快捷鍵設成同一組合。
  預期：提示「快捷鍵 ⟪組合⟫ 已被其他程式占用」，自動還原成原本設定，Log 記一筆 `ERROR`。

- [ ] **案例 28：Single Instance 正常。**
  操作：啟動一份 MousePilot（縮在 Tray）→再雙擊 `MousePilot.exe` 啟動第二份。
  預期：不會多開，原實例 Dashboard 自動跳出並取得前景焦點，第二個程序自行結束、不留任何副作用。

### Configuration（29~31）

- [ ] **案例 29：設定保存。**
  操作：修改任一設定值（例如「移動像素」），觸發保存（關閉程式，或任何呼叫 `SaveSettings` 的路徑）。
  預期：`%AppData%\MousePilot\settings.json` 內容更新為新值。

- [ ] **案例 30：重開程式設定保留。**
  操作：接續案例 29，重新啟動 MousePilot。
  預期：Dashboard 載入的設定與關閉前一致。

- [ ] **案例 31：settings.json 損毀不 Crash。**
  操作：手動把 `settings.json` 改成無效 JSON（例如刪掉一個大括號）後啟動程式。
  預期：程式正常啟動、不 crash；損毀檔案被備份為 `settings.json.corrupt-yyyyMMdd-HHmmss.bak`；改用內建預設值；Dashboard 出現非侵入式提示；Log 記一筆 `ERROR: 設定檔損毀，已載入預設值`。

## 2. 補充驗證（歷代 Phase 累積，去重整合——僅列 §34 未涵蓋的差異項）

- [ ] **Explorer 重啟後 tray icon 自動重建。**
  操作：MousePilot 執行中，用工作管理員重新啟動「Windows 檔案總管」（`explorer.exe`）。
  預期：系統匣圖示自動重新出現（不需要重開 MousePilot），右鍵選單功能正常。

- [ ] **關閉視窗＝縮到系統匣 vs. 直接結束的切換。**
  操作：取消勾選「系統設定」卡片的「關閉視窗時最小化至系統匣」後，按 Dashboard 右上角 X。
  預期：程式直接完全結束（等同系統匣「結束」），而非縮到系統匣；重新勾選後行為改回縮到系統匣。

- [ ] **工作管理員停用開機自啟的偵測。**
  操作：勾選開機自啟後，到工作管理員「啟動」分頁把 MousePilot 設為「已停用」，重新啟動 MousePilot。
  預期：Dashboard 的「Windows 開機時自動啟動」勾選框顯示為未勾選（因為實際上工作管理員已標記停用、登入不會真的執行）；重新勾選一次可清除停用旗標並讓開機自啟重新生效。

- [ ] **EXE 搬移後 Run key 路徑自動更新。**
  操作：開機自啟勾選狀態下，把 publish 的 EXE 複製到另一個資料夾並從新位置執行。
  預期：`HKCU\...\Run` 的路徑自動更新為新的 EXE 位置（自我修復）。

- [ ] **等價快捷鍵查重（非純文字比對）。**
  操作：把「啟動/暫停」與「恢復 Windows 游標」兩個快捷鍵欄位設成實際按鍵相同但錄製順序/文字表示可能不同的等價組合。
  預期：提示「快捷鍵不可與另一項重複。」，設定被拒絕還原。

- [ ] **匯入損毀檔案不留殘檔。**
  操作：把一個文字檔改副檔名為 `.png` 後嘗試匯入。
  預期：顯示錯誤訊息、不 crash，`%AppData%\MousePilot\Cursors\` 目錄中沒有殘留任何檔案。

- [ ] **收藏加入/移除持久化。**
  操作：在編輯器把某個圖案加入「我的收藏」，關閉程式後重新啟動並打開編輯器。
  預期：該圖案仍出現在「我的收藏」清單中（持久化於 `settings.json`）。

- [ ] **JPG 去背全背景退化警告。**
  操作：匯入 JPG 並勾選「移除背景（JPG 建議）」，把「容差」調到極高（例如 255）。
  預期：出現退化警告「去背後沒有可見內容——請降低容差或關閉去背。」，且不會產生可套用的游標檔（不能誤按套用出一個全透明游標）。

- [ ] **Windows 登出/重新登入後游標正常。**
  操作：套用自訂游標狀態下，登出 Windows 再重新登入（或重新啟動）。
  預期：重新登入後 Windows 游標為正常（非自訂）樣式——`SessionEnding` 事件已觸發恢復，登入時 Cursor Scheme 本就會重載。

- [ ] **強殺後 marker 補救（游標恢復）。**
  操作：套用自訂游標狀態下，用工作管理員強制結束 MousePilot 程序（不經過正常結束流程），再重新啟動 MousePilot。
  預期：強殺當下游標留在自訂樣式（OS 層限制，MousePilot 無法攔截強殺）；但重新啟動 MousePilot 時，程式偵測到 `cursor-applied.marker` 存在，會先自動執行一次恢復，才繼續正常啟動（之後若 `customCursorEnabled` 仍為真，會再自動套回）。

- [ ] **`--restore-cursor` 命令列緊急恢復。**
  操作：套用自訂游標狀態下，直接在命令列或「執行」對話框執行 `MousePilot.exe --restore-cursor`（可在已有一份 MousePilot 正在執行的情況下測試）。
  預期：立即恢復 Windows 游標並結束，不顯示任何視窗；**不受單一實例限制**，即使已有一份 MousePilot 在跑，這個指令仍能獨立執行恢復動作。

- [ ] **confirmed-cursor.cur 手動刪除後套用失敗提示。**
  操作：把 `%AppData%\MousePilot\confirmed-cursor.cur` 手動刪除，再按 Dashboard「套用」。
  預期：顯示「套用游標失敗（檔案可能已損毀或被移除）。」，不 crash，且不會誤留「已套用」的假象狀態。

- [ ] **單一實例四步驗證。**
  操作依序：① 啟動一份（縮在 Tray）→再啟動第二份，確認不多開、原視窗跳出；② Dashboard 開著時再啟動第二份，確認視窗還原/取得前景；③ 工作管理員強殺後重新啟動，確認正常啟動（abandoned mutex 接手，無需手動處理）；④ 套用自訂游標狀態下啟動第二份，確認游標不變（第二實例不誤觸補救）且 Dashboard 正常跳出。
  預期：四步皆如上所述，第二實例任何情況下都不建立新的 VM/Hook/游標動作。

- [ ] **單一實例 per-user 隔離（可選——需兩個 Windows 使用者帳戶）。**
  操作：使用者 A 啟動 MousePilot 後，切換到使用者 B（不登出 A），在 B 帳戶下啟動 MousePilot。
  預期：B 可以正常啟動自己的一份（單一實例限制為 per-user，不跨 Windows 使用者），兩份互不干擾。

- [ ] **單一實例 fail-open 訊息。**
  操作：（一般環境不易重現，若條件允許可用權限受限的測試環境模擬具名 kernel object 無法建立）觀察此情境下的啟動行為與 Log。
  預期：程式仍正常啟動（不會啟動失敗），但 Log 記錄一筆 `[ERROR] 單一實例 mutex 建立失敗（kernel object 名稱被占用或拒絕），以 fail-open 模式啟動——本次執行失去單一實例保證`。

- [ ] **Error 紅點狀態與解除。**
  操作：讓滑鼠移動連續失敗 3 次（例如暫時以除錯環境模擬 Win32 呼叫失敗，或參考單元測試涵蓋的邏輯路徑），觀察 Dashboard 狀態；之後按「暫停」再按「啟動」。
  預期：連續失敗第 3 次後狀態點變紅色「錯誤（滑鼠移動失敗）」，此狀態下「啟動」按鈕不可按；按「暫停」解除紅點後，再按「啟動」可重新開始監控。

- [ ] **數值超界輸入的夾制回填。**
  操作：把「開始閒置」欄位手動改成 `0`（或超過 86400 的極大值），按「啟動 MousePilot」。
  預期：欄位不會在輸入當下被擋下，但按下「啟動」後數值立即被夾制回合法範圍（`0` 會變回下限 `5`）並回填到欄位。

- [ ] **快捷鍵大小寫格式驗證（手動改 settings.json）。**
  操作：關閉程式後手動把 `settings.json` 的 `toggleHotkey` 改成小寫（如 `ctrl+alt+f9`），重新啟動。
  預期：程式**不會**自動修正大小寫，該快捷鍵被判定無效並直接停用，Dashboard 出現「快捷鍵設定「⟪內容⟫」無效，⟪功能⟫ 快捷鍵未啟用。」提示，Log 記一筆 `ERROR`。

- [ ] **balloon 通知（tray-only 狀態可見性）。**
  操作：把 Dashboard 縮到系統匣（視窗不可見），按 `Ctrl+Alt+F10` 恢復游標（或觸發任一會產生 Notice 的動作）。
  預期：跳出 3 秒的系統匣 balloon 通知（例如「已恢復自訂游標。」/相應文字）；連續觸發同一則文字內容時，只有第一次彈出 balloon，重複內容不重複彈出。

- [ ] **balloon 已知限制——啟動期通知不彈。**
  操作：先把 `settings.json` 改壞（製造啟動期 Notice），以預設「啟動後最小化到系統匣」設定啟動程式。
  預期：**不會**出現 balloon（啟動期視窗建構中的通知為已知限制），但 Log 有對應 `ERROR` 記錄，開啟 Dashboard 可看到殘留的提示文字。

- [ ] **Log 檔輪替觀察。**
  操作：（可用長時間執行或人工把 `mousepilot.log` 內容灌到接近/超過 5MB 來加速驗證）觀察 Log 檔案是否於超過 5MB 時觸發輪替。
